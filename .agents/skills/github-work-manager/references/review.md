# REVIEW

Read issue ACs, PR, existing comments, and unresolved review threads. Associate each feedback item with issue/PR and classify: correctness defect, missing AC, test gap, scope clarification, enhancement/new requirement, or unrelated suggestion.

Authorized in-scope corrections go onto the same PR. Re-run focused tests, update evidence with exact new head SHA, and reply with commit and evidence. Resolve a thread only when its concern is addressed. Out-of-scope requests become proposed separate work for triage; do not implement. For disputed requirements ask the user. Material scope/contract change returns NEEDS_REPLAN. Never create another feature PR for review fixes.

Report classification, correction/commit, checks, and outstanding feedback.
